讲点：AI 账单最怕"跑飞"。网关可以给整个团队（Workspace）和每个应用 / 每个人（Key）分别封顶，任何一层用完都会被 HTTP 412 拦下，不再产生费用。现场看："客服机器人"只有 200 token 额度，用完之后的请求立即被拒；同一个团队的"研发 Copilot"照常工作——一个应用超支，不影响其他应用。

第一层 · Workspace 预算

团队总共能花多少
按金额或 Token；不重置/每周/每月；超出返回 412 "Integration … Usage Limit Exceeded"

第二层 · Key 预算

每把 Key 独立额度 + 告警阈值；超出返回 412 "API Key Usage Limit Exceeded"，Key 状态变为 Exhausted

安检 Config 示例（负载均衡 + 输入/输出安检，拦截时返回 HTTP 446）。模型写成 @接入短名/模型名：

{
  "strategy": { "mode": "loadbalance" },
  "targets": [
    { "model": "@<接入短名A>/<模型名>", "weight": 0.5 },
    { "model": "@<接入短名B>/<模型名>", "weight": 0.5 }
  ],
  "input_guardrails":  [{ "id": "<Guardrail ID>", "deny": true }],
  "output_guardrails": [{ "id": "<Guardrail ID>", "deny": true }]
}

单模型 + 安检（换用其他 LLM 时最简单的写法：先在 LLM Integrations 新增接入，再把这里的模型换掉）：

{
  "strategy": { "mode": "single" },
  "targets": [{ "override_params": { "model": "@<接入短名>/<模型名>" } }],
  "input_guardrails":  [{ "id": "<Guardrail ID>", "deny": true }],
  "output_guardrails": [{ "id": "<Guardrail ID>", "deny": true }]
}

缓存 Config："cache": { "mode": "simple", "max_age": 600 }（精确匹配，改一个字就不命中）。条件分流 Config：strategy.mode = "conditional"，按请求头 x-portkey-metadata 里的 x-task 选目标；conditions 的具体字段写法以控制台编辑器为准（待核实）。
